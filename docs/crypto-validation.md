# 密码学上游敏捷验证（2026-11-05）

目的：在改动 OhMyKei 生产核心前，用小型独立探针比较两条已收敛的路线。
本轮只验证原语行为、未修改上游的构建可行性和 Cortex-M33 ELF 链接；没有接入
CTAP、运行候选固件或声称通过硬件侧信道验证。项目自有代码继续 MIT。

## 固定输入

- TF-PSA-Crypto 1.1.1（LTS）官方源码包，Apache-2.0 许可路径。
- BearSSL 官方快照 `7bea48e`，MIT。使用 `br_ec_p256_m31`、i31 ECDSA、`aes_ct`。
- 两者均搭配 libsodium 1.0.22，ISC；`--enable-minimal --disable-shared --disable-asm`。
- 主机 Apple Clang；ARM 为 arm-none-eabi-gcc 14.2.1、Cortex-M33、Thumb、`-Os`。
  ARM 开启 function/data sections 与链接 GC。无 LTO。
- 三份源码包的全部原始普通文件在构建后逐字节哈希对照，均无修改。
- 所有输入均为标准公开向量或合成数据；探针不输出密钥、签名或其他原始载荷。
  探针 RNG 明确为测试专用，不能复制到固件。

## 结果

| 验证 | BearSSL + libsodium | TF-PSA + libsodium |
|---|---:|---:|
| 未修改上游的主机构建 | 通过 | 通过 |
| 未修改上游的 Cortex-M33 静态库构建 | 通过 | 通过 |
| 共同主机检查 | 19/19 | 19/19 |
| PSA 熵源失败、恢复、释放后池占用归零 | 不适用 | 1/1 |
| Cortex-M33 ELF 链接（nosys 桩） | 通过 | 通过 |

共同检查包含 SHA-256 已知答案、RFC 4231 HMAC、RFC 5869 HKDF、NIST AES-256-CBC
加密与原位解密、P-256 生成元、确定性 ECDSA、ECDH、损坏签名／非法曲线点／零及
曲线阶私钥拒绝、RFC 8032 Ed25519 以及损坏签名拒绝。
最后一项是 16 组输入与现有 OhMyKei 实现交叉对照：双向 ECDSA/Ed25519 验签、
公钥导出、ECDH、摘要、AES-CBC、HMAC 和 HKDF。19 项包含初始化检查，不能解释为
19 个独立算法或完整 API 合约覆盖。

|---|---:|---:|---:|---:|

## 对维护成本有影响的发现

1. **两条路线均不需要修改上游原语源码即可完成本轮验证。** libsodium 裸机配置
   需 `--specs=nosys.specs`；第一次遗漏它导致编译器试链接失败，补齐后正常。
   探针初版还修正了构建目录下生成头文件的 include 路径，这些属于验证脚本问题。
   只读审查发现脚本缺少失败退出码汇总；已补齐 link/run/size 退出码检查，
   修正后重新执行全部探针，整体退出码为 0。
2. **TF-PSA 的接口适配工作较多。** 保留确定性 ECDSA，使用默认 P-256 后端，
   没有改用不支持该功能的 p256-m。配置四个静态 key slot，32 KiB 官方固定内存池，
   使用官方熵源回调及 HMAC_DRBG。固定池仍然进行动态分配。
   主机这组测试的池峰值 payload 为 4312 字节、峰值块数 66；统计不包含块头和栈，
   不能当作 ARM 内存预算。报告的分配次数为 1125426；尚未做性能归因。
   正常结束前的 336 字节占用在 PSA teardown 后归零，测试没有发现池泄漏。
3. **libsodium 不是只链接一个 Ed25519 文件。** 正常调用 `sodium_init()` 会初始化
   多个算法后端；`--enable-minimal` 后仍如此。两份 ARM ELF 都包含 libc 分配器与
   `_open/_read/_write/_sbrk` 等 nosys 桩。符号存在不等于所测签名路径执行了分配，
   但足以说明“完全无堆／无 OS 依赖”尚未证明。没有绕过官方初始化或裁剪私有源码。
4. **探针适配层还不是生产适配层。** 尚未完整处理 `omk_crypto` 的 low-S 归一化、
   RNG 回调语义、流式接口、失败输出清理及所有边界；没有据此声称可以直接替换。
   现有算法实现是交叉验证对象，不是独立安全证明；标准向量提供部分独立依据。

## 后续决定（2026-11-06 更新）

本轮数据仅证明候选库在有限探针下的构建和功能可行性，未证明迁移能降低维护成本。
目前停止第三方生产后端接入，继续维护自有实现，以 Wycheproof/NIST 公开测试数据
驱动修复和回归。新基线及接入边界见 [密码学回归](crypto-testing.md)。

上述候选库探针没有接入生产核心，也未因此重跑官方 CTAP 套件。真机执行耗时与
硬件侧信道仍需另验。

本地复查材料归档在 `backups/20261105-crypto-validation/probe-evidence.tar.gz`：
包含探针、配置、版本与哈希、链接命令、结果和资源统计，不含上游源码／构建产物。
它是一次性验证证据，不是新增长期测试框架。临时源码与构建目录完成审查后移入回收站。

子代理只读审查完成：未发现阻碍本轮有限结论的问题；唯一必要修复为上述脚本退出码传播，已修复并复跑通过。
